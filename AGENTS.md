# Photoshop Tool contributor guidance

- Work on `develop` unless the owner explicitly changes the branch scope. Do not merge into `main` automatically.
- Owner's concise Photoshop workflow/UI preferences: [docs/photoshop-preferences.ru.md](docs/photoshop-preferences.ru.md). Preserve resize/adaptation, rounded compact controls, one-action workflows, settings and easy diagnostic export.
- Run `npm test`, `npm run build`, and `npm run check`. Python's `zipfile` can independently inspect the CCX. No npm dependencies/install step.
- `package.json.version` owns the native x.y.0 version; y is one digit. The owner migrated 0.3.5 → display 1.0 / native 1.0.0. Next labels: 1.1 … 1.9 → 2.0; native 1.1.0 … 1.9.0 → 2.0.0. `scripts/version.cjs` derives display metadata and `dist/Photoshop-Tool-v<display>.ccx`; build also generates `plugin/product.json` and `plugin/manifest.json`. Do not silently change issued version bytes.
- Runtime is Photoshop UXP, not Node/browser/ExtendScript. Keep `node:*`, fs/child_process and build modules out of `plugin/`.
- Tools register in `plugin/tools/index.js`; the panel and menu consume that registry. Retain the stable plugin ID `com.nasaat.pngrelay`, panel ID `relayPanel`, original commands and legacy `pngrelay.*` preference keys.
- Resolve project-folder Entries before modal work, revalidate targets and await all host changes. The owner requested automatic export beside the PSD: `fullAccess` replaces per-folder pickers. Preserve unrelated layers, selection, document path, source save state and output recovery. History cannot undo external files/clipboard.
- Keep scope and claims precise: mocks/builds do not prove native Photoshop rendering, clipboard alpha, Defender acceptance or flicker resolution.
- Copy is visible by default and copies the entire visible composition, ignoring the source selection/active layer. Keep source layers/selection intact. PNG + Copy and Copy share a temporary merged document pipeline; do not reopen output PNGs merely to copy. Validate staged PNG dimensions/depth/mode/structure/CRCs before clipboard updates and final file replacement. This is not pixel decoding or visual verification; keep diagnostics/docs honest about it.
- Smart Object extraction lives in `tools/png/smart-object.js`: one selected pixel layer + selection uses that layer; all other layer states or no selection use Stamp Visible with `duplicate:true`. Preserve exact feathered selection with an owned alpha channel, use an explicit canvas rectangle for no-selection input, place owned helpers outside groups and retain one final Smart Object. Roll back temporary layers/channels through parent history on failure; never substitute destructive mergeVisible without duplicate.
- Never retain UXP Layer wrappers across make/merge/delete/convert. Cache primitive IDs before mutation, reacquire from the fresh layer tree, and skip cleanup of an owned helper already consumed by Stamp Visible. Use native make + identify the newly created ID when no layer is active. Regression tests must invalidate stale handles rather than keep deleted objects readable. Photoshop version is `uxp.host.version`; do not assume `photoshop.app.version` exists. Keep substep/ID/original-cause diagnostics.
- No network, native helpers, process launch or background polling. `clipboard: readAndWrite` is required by UXP for the owner's Copy report action; runtime only writes text explicitly and never reads clipboard content. PNG image copying remains native Photoshop. Preserve the report's session bounds and original errors when cleanup also fails.
- Preserve the MIT license and original project provenance: https://github.com/NasaatR/Photoshop_Tool. Product credit remains Made by Nasaat; it does not add license restrictions.

- Layer-only tools live in `tools/layers/` and share `core/layers.js` safe ID/stamp helpers with PNG extraction. They must work without file/clipboard permissions being exercised, saved paths or PNG options. Keep Convert/Camera Raw separate from Smart Area; reuse an existing Smart Object, select composite channels for layer actions, preserve exact selection and commit effect flags only after history commits. Native dialogs require explicit display + interactive modal scope; cancellation rolls back, never applies export-specific recovery text. Preserve existing masks/clipping chains and put new adjustments immediately above the intended target, including groups.

- UXP title-only tooltips were reported invisible. Use shared `ui/tooltips.js` for hover/focus hints; keep concise name-only hints on every control, panel-bounded geometry and Escape/pointer transfer. Dispose owned timers/listeners on hide/destroy; do not poll the host. Tools marked compact use the small layer toolbar, independent of export button size and saved caption preference. Skip native Move when fresh IDs already show direct-above placement.

- Mask-focused Layers actions resolve native targetLayersIDs inside executeAsModal, validate live owner IDs, and select the image/composite without reading activeChannels.kind/name. Tests must include a mask with throwing DOM getters and sequential mask → adjustment actions. Black Mask / Invert adds a black mask when absent and inverts an existing whole pixel mask when present. Save/deselect/restore exact selection around inversion, explicitly select the mask before invert, preserve source pixels/density/feather and acknowledge effects only after commit.
- Tooltip regressions must cover short panels where a full hint would overlap its own anchor, child blur/layout events, pointer transfer and teardown. Resize/scroll repositions rather than blindly dismissing. Arrange mode uses core/tool-order.js + ui/reorder.js; persist stable IDs separately under photoshoptool.order.v1, preserve hidden/new tools and sections, and never run a tool while moving it.

- Settings use View/Buttons/Actions/Help tab panels (stable internal IDs view/tools/export/help) with persistent control nodes; do not lose PNG drafts on tab switches. Keep native scrolling in an explicitly bounded panel viewport, avoid flex-child shrinking, and keep input keys separate from content paging. Tooltips show only titles; fuller instructions belong in the optional Tool guide.

- 1.2 absolute top/bottom + auto-height main scrolling content rendered blank on the owner's host while the footer stayed visible. Keep main content AND footer in normal flow. ui/viewport.js measures a positive pixel viewport height from the mounted host, with ResizeObserver/mount/show/window fallback and a single deferred pass. Never assign zero height for hidden/unmeasured hosts; keep the normal-flow fallback. Dispose observers/listeners/timers and report layout metrics. DOM/source tests cannot certify native Photoshop rendering.

- Smart Area retains png.selection-smart / selectionSmart. tools/png/soft-mask.js adds the editable mask to the parent object, not the contents/PNG. Preserve the exact selection for all extraction paths; contract with canvas bounds enabled, guard disappearing irregular regions and bake one native Gaussian Blur into the pixel mask, with Feather explicitly 0. Deselect before filtering and explicitly target the mask channel by owner/document IDs; never use a Layer filter that could affect image pixels or create a Smart Filter. Percentage is of the region’s shorter bounding-box side, default 5%, stored under photoshoptool.smartArea.v2; 0 skips blur. Preserve the old pixel preference under v1 and old zero behavior; never interpret its px value as percent or rewrite existing masks. The native radius is bounded to 0.1–250 px with requested/effective values reported.
- Fill Current Layer transforms exactly one valid owner layer with proportional cover + centering, not the pixel selection/mask; retain one history step and reject empty/locked/linked targets before mutation. Quick PSD is a separate tools/psd service: local image → native layered PSD beside it → continue in PSD, collision numbering, existing PSD/PSB save in place. No flattening/conversion, no automatic overwrite of another PSD, no deletion of uncertain document-backed output. PNG export options do not govern these tools.

- Expand Selection lives in tools/selection, defaults to 8 px, and accepts the native integer range 1–500 px under photoshoptool.selection.v1. Use exact Selection.expand(amount, false), never a bounding-box rectangle or layer mutation. Reject missing selection/Quick Mask; revalidate the document inside modal work and roll back each command in one history scope. Fill, Expand, Camera Raw and Mask / Invert are standard-size Area & transform tools; Smart Object, Curves, Hue/Sat and Solid Color stay compact. Keep format text visible with captions hidden.
- Action parameter saves/reset must be scoped: invalid PNG/Smart Area/selection drafts cannot block saving another group. Keep drafts on errors, acknowledge Saved only after setItem, and persist last settings tab separately under photoshoptool.settingsTab.v1. Preserve the v1.3 viewport flow/cleanup.

- Main tool rows use four-column flex flow, minimum 44 px hit widths (76 px with captions), automatic wrap and 40/48 px icon heights. Keep Layers compact and normal-flow viewport intact. Optional appearance.buttonSize (integer 36–4096 px) overrides the main height; density presets clear it and Reset uses the current preset. Preserve existing appearance keys and absent overrides.
- ui/sliders.js pairs native sp-slider controls with exact numeric entry: preview on input, persist on change, reset/double-click synchronization, stable rails during drag and disabled state. Convenience rails extend for valid typed values without restricting domain limits. Do not rebuild controls or execute Photoshop operations while dragging settings. Avoid rewriting unchanged sizing rules/classes/native slider properties; retain invalid drafts and truthful save feedback.

- Settings live in a single native uxpShowModal dialog, not inline. ui/settings-window.js owns revision-guarded open/close/error/disposal; preserve live controls, drafts, last tab and independent main scroll. ui/viewport.js sizes the dialog scroll above its normal-flow footer. Derive dialog styling from canonical scoped CSS and mirror appearance classes. Use separate tooltip roots/IDs; Escape dismisses a hint before closing settings. Document commands must not run while settings are open. Native dialog checks remain distinct from DOM mocks.
- ui/focus.js tracks only keyboard/pointer modality; show custom focus rings through data-keyboard-focus, clear on pointer input and remove owned listeners on disposal. Do not restore a keyboard frame after native titlebar dismissal. The Lucide Expand icon retains path-level fill=none and its source/license; package LICENSE-LUCIDE.txt alongside the original license.
