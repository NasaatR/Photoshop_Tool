# Photoshop Tool

A modular Adobe Photoshop UXP toolbox by NasaatR. It combines full-resolution PNG export/copy with Smart Objects, Camera Raw, masks, clipped adjustments and color fills. New bundled tools share the same panel, command registry, preferences, single-flight execution and host/file safety helpers.

## Download and install

**Development preview 1.8:** [Download Photoshop-Tool-v1.8.ccx](https://github.com/NasaatR/Photoshop_Tool/raw/refs/heads/develop/dist/Photoshop-Tool-v1.8.ccx). This is the installable plugin, not GitHub's source ZIP. [SHA-256](dist/SHA256SUMS.txt).

1. Close Photoshop. Double-click the `.ccx` file and approve installation/update in Creative Cloud Desktop.
2. Open Photoshop → **Plugins → Photoshop Tool → Photoshop Tool**.
3. Approve the updated file/clipboard permissions during installation. Export finds the saved PSD's folder automatically; no folder picker is shown.

UXP Developer Tool is not required for CCX installation. This updates the earlier **PNG Relay**: plugin ID `com.nasaat.pngrelay`, original menu command IDs, export preferences and folder-access keys are preserved. Unload any development copy in UDT before installing the CCX. To uninstall, use Creative Cloud Desktop → Manage Plugins → Photoshop Tool → Uninstall. Exported files remain.

Code is in **develop**, as requested by the repository owner. `main` is deliberately unchanged. This CCX is a checked repository download, not an Adobe Marketplace submission or a GitHub Release asset.

## Included tools

| Tool | Behavior |
| --- | --- |
| PNG + Copy | Current visible canvas → lossless PNG beside the local PSD/PSB, then image data for native paste. |
| Copy | Full visible composition as one image, ignoring the selection/selected layer. No PNG, folder access or disk staging. Also works on an unsaved document. |
| Smart Area | Pixel selection or full canvas → new embedded Smart Object + editable soft parent mask → open contents → PNG beside parent PSD + copy. Creates a visible composite when needed. |
| Quick PSD | Save an image as a layered PSD beside its original and continue working in the PSD. Existing PSD/PSB projects save in place. Name conflicts get a numbered filename. |
| PNG only | Export without changing the image clipboard. Works even when Export Clipboard is disabled. |
| Smart Object | Convert selected layers in place. With no selected layer, create a nondestructive Stamp Visible copy first. An existing Smart Object is reused. No extraction, export or contents opening. |
| Camera Raw | Same target logic, then open the native Camera Raw dialog. OK applies it as an editable Smart Filter; Cancel rolls back this command. |
| Mask | Add a full black Hide All pixel mask, or invert the entire existing pixel mask on one unlocked selected layer/group. Existing mask density/feather and source pixels are preserved. Unlock a special Background layer first. |
| Curves | Add a neutral Curves adjustment immediately above one selected layer/group and clip it. |
| Hue / Sat | Add a neutral Hue/Saturation adjustment immediately above one selected layer/group and clip it. |
| Solid Color | Choose a color in the native picker and create an editable, unclipped fill. Cancellation adds nothing. |
| Fill Layer | Scale one unlocked layer proportionally to cover the document canvas and center it; overflow stays outside the canvas. Does not resize the canvas or rasterize the layer. |
| Expand Selection | Grow the existing pixel selection outward by 8 px per click by default. Set an exact 1–500 px amount in Actions settings. No file or selected layer is needed. |

The **Export & copy**, **Area & transform** and compact **Layers** sections keep frequent actions separate from the small layer toolbar. PNG/PSD save glyphs contain persistent format names even when captions are hidden. Fill Current Layer, Expand Selection, Camera Raw and Mask / Invert use the same large button tier as saving and Smart Area. Smart Object, Curves, Hue / Sat and Solid Color remain compact. All tools except PNG only are visible by default; existing visibility overrides remain respected. **Gear → Buttons** controls each button. All thirteen commands also appear in Photoshop's Plugins menu. Existing command IDs remain stable, including `selectionSmart` (now labeled Smart Area) and `copyImageOnly`. Copy transfers image data for Ctrl+V, not file paths or separate layers. Hidden layers stay excluded from the composition.

The seven layer tools work in unsaved documents, require no export-folder access or external clipboard preference, and ignore unrelated PNG options. Smart Object and Camera Raw act on whole selected layers, preserving the pixel selection via an owned alpha channel. No selected layers means a full visible stamp, without merging/deleting original layers. Selecting multiple layers embeds them together; a selected group embeds its descendants. Layer actions select the composite image channel when a mask/channel was active. Black mask selects its new mask for painting afterward.

Curves/Hue / Sat require exactly one selected target; edit them in Photoshop's Properties panel. A current pixel selection follows native adjustment-mask behavior. Existing clipping chains keep Photoshop's base-layer/group semantics. Solid Color follows native insertion/selection-mask behavior; when inserted into a clipping chain, it is moved above that chain before unclipping so existing clipped layers are not released. Layer operations share one history step and roll back on failure/cancellation. An already-smart Convert command is a no-op and does not create a history/selection channel.

The panel now uses rounded filled tool buttons with visible captions, consistent 24-unit SVG icons, a distinct report icon, a status indicator and grouped options. A one-time design refresh enables captions/rounded corners while retaining theme, density, export settings and button visibility; later changes are respected. The label toggle, compact/roomy size, Square/Rounded corners and Auto/Dark/Light theme are retained. Auto follows Photoshop's host colors. Export buttons retain their larger layout. Layers use compact 32×32 px icons (Roomy: 36×36), wrapping as needed rather than stretching into two large columns. With captions, Layers use three columns and shorter 56/62 px buttons. Hidden empty sections take no space. Every tool, setting and report control has a compact name-only hover/focus hint; it does not rely on the host rendering HTML title. Hints stay inside the panel, allow pointer transfer, dismiss with Escape and clean up on hide/destroy. No idle timer, document polling or tooltip animation is used. Captions can be hidden for a compact icon toolbar.

Drag the floating panel's edge/corner or a dock divider to resize. The manifest explicitly permits 176×96 through 4096×4096 pixels; Photoshop's docking layout may impose additional limits. Tools and reports share one normal-flow scroll viewport at small sizes. Settings open in a separate native resizable window with their own viewport and Close footer. It never depends on top/bottom offsets with auto height; native vertical scrolling appears on overflow. It supports wheel scrolling plus Page Up/Page Down, and Home/End when the content region is focused. This is based on the panel dimensions, not detection of overlap by other OS windows. ## Smart Area, Fill Current Layer and Quick PSD

**Smart Area** replaces the Extract + PNG label while retaining `png.selection-smart` / `selectionSmart`, visibility and saved order. Its new pixel mask is on the Smart Object in the **parent document**. The contents document, exported PNG and clipboard keep the extracted artwork without this parent mask, so it remains suitable for round-trip editing. **Settings → Actions → Smart Area → Edge blur · %** defaults to 5%; accepts 0–100%, including decimals. Radius is a percentage of the region’s shorter bounding-box side: 1000×600 px at 5% uses 30 px. Zero skips blur. The radius follows the documented native Gaussian range of 0.1–250 px; diagnostics record requested/effective radius and any limiting. The mask outline is inset, with a nonempty center retained; a disappearing narrow selection falls back to its exact original outline with a warning.

From **1.5**, blur is applied **once to the pixel mask itself**, with an explicit mask channel target and no active pixel selection during filtering. The mask’s live **Feather stays 0**: later painting/erasing remains ordinary mask editing rather than being softened again by a persistent parameter. It is not a Smart Filter. No JavaScript image buffers, extra documents or repeated filter passes are added. Exact selection restoration and mask/extraction rollback stay in the parent history step. An update does not rewrite existing masks or brush work.

The percentage preference uses `photoshoptool.smartArea.v2`. The previous pixel preference remains untouched in `photoshoptool.smartArea.v1`: a stored zero remains zero, while other old pixel amounts start at the new proportional default of 5%, since pixels cannot be converted to a fixed percentage without a region size. New percentage edits autosave independently of the old pixel preference.

**Fill Current Layer** uses proportional cover, not stretching: for example, a square image filling a wide canvas extends above/below it. It transforms the whole selected layer even when a pixel selection or layer-mask thumbnail was active. Select exactly one unlocked, nonempty layer/group/Smart Object. Linked layers must be unlinked first to prevent changes to other linked layers. Originals outside the selected layer/group and the canvas stay intact; the full operation is one undo step. It works in unsaved documents without file/clipboard access. It does not add image detail when enlarging pixels.

**Quick PSD** uses Photoshop's native PSD save with layers, alpha/spot channels, annotations, embedded profile and compatibility enabled. For a local PNG/JPEG/TIFF or other image, it uses the same folder/base name and makes the PSD the working document; the original image is untouched. A pre-existing or open same-name PSD gets a numbered alternative, never an automatic overwrite. Clicking again saves that PSD normally. Existing PSD/PSB files save in place. Unsaved/cloud documents ask for a local PSD destination; Cancel creates nothing. A new PSD with a canvas beyond 30,000 px is refused with PSB guidance; native PSD size/format errors remain visible without flattening/conversion. A rejected save removes only an owned partial file; uncertain output already bound to the document is retained with a warning. This is a native-save acknowledgement, not reopened-file visual verification.

The 1.3 panel flow/scroll fix remains intact. New buttons use the existing icon family, keyboard actions, hover hints, visibility controls and ordering. The two additions have no PNG-option or clipboard dependency. Native Photoshop acceptance still needs: inspect the parent mask edge, confirm Feather is 0 and paint a hard white/black stroke without automatic softening, check exported contents, fill portrait/landscape layers, and create/reopen a layered PSD while verifying the original image is unchanged.

Implementation references: [Selection.contract](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/classes/selection/), [Layer mask feather/scale/translate](https://developer.adobe.com/photoshop/uxp/ps_reference/classes/layer/), [Document saveAs](https://developer.adobe.com/photoshop/uxp/ps_reference/classes/document/), [PhotoshopSaveOptions](https://developer.adobe.com/photoshop/uxp/2022/ps-reference/objects/saveoptions/photoshopsaveoptions/).

## Export behavior and limits

- Windows 11; Photoshop **26.9+**, UXP API v2. Version 0.1.1 was reported working by the user. This 1.8 build has not been executed in a real Photoshop host here.
- Original canvas dimensions and source 8/16-bit depth; RGB/Grayscale only. No lossy compression or arbitrary resizing. Other modes and 32-bit/HDR are refused instead of silently converted. Optional sRGB conversion changes only the temporary copy.
- PNG uses current in-memory artwork, including unsaved edits. It does **not** automatically save/flatten the source PSD. Artboards export the full document canvas, not separate board files.
- Smart Area input follows the table below. The visible-composite path uses native Stamp Visible (`mergeVisible` with `duplicate: true`, equivalent to Shift+Ctrl+Alt+E) on an owned temporary pixel layer at the top. Original layers remain editable and hidden layers stay excluded. The full stamp and helper are removed after extracting the region, leaving exactly one new Smart Object. The original pixel selection is saved/loaded through an owned alpha channel to preserve its exact feathered/nonrectangular shape. Extraction applies that shape; Smart Area then adds a separate soft mask on the parent object. The temporary channel is removed afterward. No selection means an explicit full-canvas rectangle, including when artboards are present; the original no-selection state is restored. Quick Mask and non-composite channels are still refused. Native Photoshop masks/styles/blending semantics apply.
- The new Smart Object contents stay open. Use PNG + Copy inside them to update the same derived PNG in this plugin session. Undo in the parent affects scene edits, not files or clipboard. Unrecognized temporary PSBs are refused.
- Copying uses Photoshop's native image clipboard. Receiving applications decide formats, bit depth, transparency and transparent-border handling. Universal paste/alpha support is not claimed. Enable Photoshop Export Clipboard with the explicit panel button if offered.
- PNG export now uses one temporary merged document for both saving and copying, then closes it and restores focus. It does **not** reopen the PNG in Photoshop. Before any clipboard change or file replacement, the plugin reads the staged PNG as binary and checks signature, dimensions, bit depth/color mode, chunk boundaries/order, image-data presence, ending and every chunk CRC. This reads the compressed file into memory; it is a structure/integrity check, not a pixel decode or visual/ICC comparison. Diagnostics record `verification.method` and `decodedPixels: false` honestly. Copy uses no PNG read/open/write. Neither action changes the original selection or merges source layers.
- Removing the PNG open/close cycle eliminates one document opening from each export. A temporary merged document and native save/copy operations remain and may still redraw Photoshop. Reduced document switching is source/mocked evidence; actual flashing has not been reproduced or confirmed fixed. There is no background polling, animation, forced redraw or idle Photoshop mutation.

| State when Smart Area is clicked | Input |
| --- | --- |
| One pixel layer + pixel selection | Selected pixel layer's own content, as before. |
| Text, group, adjustment, Smart Object, multiple or no selected layers + pixel selection | All visible artwork, cropped by the exact selection. |
| No pixel selection | Visible composite of the full canvas, regardless of active layer. |

Composite preparation, extraction and conversion share one parent-document history step. Errors before conversion commits roll back owned layers/channels. Errors during later PNG export retain the new Smart Object and its open contents for retry. Empty visible artwork reports an error instead of converting an original layer.

## Recovery, data and permissions

Filesystem permission is **fullAccess** so the requested export beside a saved PSD needs no folder picker. Runtime resolves and verifies only the intended project-folder Entry for each export, using UXP's storage provider. Old folder-token settings remain untouched but are no longer needed. `clipboard: readAndWrite` is UXP's permission required for **Copy report**; the plugin only writes diagnostic text on that explicit action and never reads the clipboard. Image copying still uses Photoshop's native image commands. No network, process launch or native helper. Nothing is uploaded. Copy only writes no files; diagnostic text is exported only by its own buttons.

Before PNG replacement, the old file is moved to an operation-specific backup. Failed replacement attempts restore the backup when possible, retaining a direct handle instead of depending on a second file lookup. This is recovery handling, not an atomic filesystem transaction. Do not run simultaneous exporters on one output path. A PNG already open in Photoshop blocks replacement. Crashes or disk failures can leave `.photoshoptool-export-*` or `.photoshoptool-backup-*` files beside the PSD; inspect them before cleanup. Never delete a pre-existing PSD to recover an export.

PNG commit, clipboard updates and parent-document edits are separate effects. Partial success is reported accurately. If selection export fails after creating the Smart Object, keep its contents and retry PNG + Copy there. If copying fails, a valid PNG can still be saved. If PNG replacement fails after copying, the clipboard may already be changed.

**Copy report** is the copy icon beside the status line and is also under **gear → Help & report**. It writes text ready for Ctrl+V, replacing the current image clipboard. **Save report .txt** in the same section saves that report with a file picker and keeps the clipboard unchanged. Reports contain host/plugin versions, panel size, settings, source dimensions/mode/depth, acknowledged effects, timestamped steps, failure phase, error codes/stacks/causes and cleanup errors. The journal keeps the last eight operations and 100 events in memory for the current plugin session, including option-validation and report-export failures; a later success does not erase earlier errors. It is not a Photoshop-wide or persistent crash log. Local absolute paths are redacted; output filenames/error text can remain, so review before sharing. Nothing is sent automatically.

## Add a tool

See [docs/adding-tools.md](docs/adding-tools.md). A bundled module declares a stable tool ID, existing/custom icon, menu command ID, labels and an async handler. Register the module once in `plugin/tools/index.js`; the UI and generated manifest use that registry. Tool-specific option validation is optional and does not block unrelated tools. No editing the runner or hardcoded panel buttons is required.

| Location | Responsibility |
| --- | --- |
| `plugin/core/` | Registry, single-flight runner, bounded diagnostics, host/modal/history helpers, legacy preferences, direct project-folder access and safe file commit. |
| `plugin/tools/png/` | PNG/copy/extraction definitions, logic and service. |
| `plugin/tools/layers/` | Convert/Camera Raw/mask/adjustment/fill commands and service; no file/clipboard dependency. |
| `plugin/ui/` | Registry-driven panel, separate settings window, bundled SVG icons and scoped theme-aware styling. |
| `plugin/main.js` | Dependency wiring and one UXP entrypoint registration. |
| `scripts/` | Manifest generation, dependency-free reproducible CCX packaging and runtime checks. |
| `tests/` | Node tests with mocked Photoshop/storage/DOM boundaries. |

For developers: Node.js 22+, no npm dependencies or install step. `npm test`, `npm run build`, `npm run check`. `package.json` is the version source; build generates runtime metadata/manifest and `dist/Photoshop-Tool-v<display>.ccx` with `LICENSE.txt` and `LICENSE-LUCIDE.txt`. The archive is standard ZIP-based CCX, with `manifest.json` at its root, built using Adobe's documented independent packaging format. Runtime code never imports Node build/test modules.

The GitHub check workflow runs tests, build/source checks and a byte-for-byte comparison with the committed installer. It has read-only repository permission and does not publish/deploy. Native host tests are still required before describing a build as stable. Never silently replace an issued version with different bytes.
